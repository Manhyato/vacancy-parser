# Отчёт по заданию 7: Deadlock, Livelock и Starvation
## 🔹 1. Цель работы

Реализовать и проанализировать три типа проблем многопоточности:

**Deadlock** (взаимная блокировка)

**Livelock** (активное ожидание без прогресса)

**Starvation** (голодание потоков)

Также продемонстрировать способы их диагностики и предотвращения.

## 🔹 2. Этапы выполнения
**2.1. Deadlock**

Созданы два потока:

Поток 1 захватывает resourceA, затем resourceB

Поток 2 захватывает resourceB, затем resourceA

Это приводит к классической взаимной блокировке, когда оба потока ждут освобождения ресурсов друг от друга.

**Пример вывода:**

Thread-1 acquired resource A
Thread-2 acquired resource B
(программа зависает)


**Диагностика выполнялась через:**

jps        # для получения PID процесса
jstack <PID>


Фрагмент дампа:

Found one Java-level deadlock:
Thread-1: waiting to lock monitor 0x000001c1e4b3c8b8 (object resourceB)
Thread-2: waiting to lock monitor 0x000001c1e4b3c8a0 (object resourceA)


Причина: потоки захватывают ресурсы в разном порядке.
**2.2. Livelock**

Два потока ("Alice" и "Bob") постоянно уступают друг другу, не блокируясь, но и не продвигаясь в выполнении задачи.

**Вывод программы:**

=== Демонстрация Livelock ===
Alice уступает место Bob
Bob уступает место Alice
...
Bob не смог выполнить (livelock)
Alice не смог выполнить (livelock)


Причина: потоки слишком “вежливы” и постоянно меняют состояние, не выполняя задачу.
**2.3. Starvation**

Несколько потоков имеют разные приоритеты. Поток с низким приоритетом (Hungry) не получает доступ к ресурсу.

**Вывод программы:**

=== Демонстрация Starvation ===
Hungry: возможно starvation ? не получил lock


**Причина:** поток с низким приоритетом постоянно проигрывает конкуренцию при захвате блокировки.
## 🔹 3. Промежуточные результаты
Тип проблемы	Поведение	Симптом	Решение
Deadlock	Потоки блокируются навсегда	Программа зависает	Упорядочивание блокировок
Livelock	Потоки активны, но без прогресса	Цикл уступок	Таймауты, случайные задержки
Starvation	Один поток не получает доступ	Задержка слабого потока	Справедливые блокировки, yield()
## 🔹 4. Выводы

Deadlock возникает при неправильном порядке захвата ресурсов.

Livelock демонстрирует активность без прогресса — поток “занят”, но неэффективен.

**Starvation** — результат несправедливого доступа к ресурсу.

Использование ReentrantLock, таймаутов, и справедливых политик блокировок позволяет избежать всех трёх ситуаций.
